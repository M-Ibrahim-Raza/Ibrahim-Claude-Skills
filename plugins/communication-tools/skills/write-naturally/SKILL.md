# Write Naturally

Rewrites or drafts content so it sounds simple, clear, natural, and like a real person wrote it — not robotic or AI-generated. Useful for emails, Slack messages, documentation, blog posts, comments, and replies.

- Use plain, day-to-day language. Short declarative sentences, present tense, no second person.
- Keep sentences the length a person would actually say out loud — mix short and medium sentences for natural rhythm, and break up long ones.
- Avoid AI-sounding patterns: no robotic em-dash piles, no padded closing summaries.

## When to use
- Writing or rewriting Slack messages, emails, or chat replies
- Making documentation feel approachable
- Replacing robotic or AI-sounding text with natural, simple writing
- Any time the user asks for content that is "simple," "clear," "casual," or "easy to understand"

## What to avoid
- Jargon and buzzwords ("synergize," "leverage," "circle back," "low-hanging fruit")
- Overly formal phrases ("Please be advised that," "Kindly find attached")
- Fancy words where a plain one works ("commence" → "start," "facilitate" → "help")

## Banned AI tells (lexical)

These aren't wrong in isolation, but their overuse is a signature of machine writing. Exception: if a banned word is the genuinely correct technical term (e.g., "robust" in a statistics context, "navigate" for actual UI navigation), use it — the rule targets filler, not accurate terminology.

- **Words**: delve, leverage (as a verb), robust, seamless, seamlessly, foster, harness, utilize (use "use"), underscore, tapestry, landscape (figurative), realm, navigate (figurative), unlock, elevate, empower, streamline, cutting-edge, game-changer.
- **Openers**: "In today's fast-paced world…", "In the ever-evolving…", "When it comes to…".
- **Em-dash pile-up**: don't lean on em-dashes for every aside — a comma or full stop is often better. Use them sparingly and deliberately.
- **Adjective stacking**: "a powerful, intuitive, comprehensive solution." Pick one true adjective or none.
